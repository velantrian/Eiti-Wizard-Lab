# Working Memory — Gate B1: Agent Read Bridge + Working/Research Separation

STATUS: `NON_CANON` · READ-ONLY from the agent perspective · baseline `72c5f7f06a254798accb2ccde77801cbb7b82aef` (Gate A).

## Two planes

| | Working Plane | Research Plane |
|---|---|---|
| Source | Working Memory `wm_*` | `docs/research/EXPERIMENT_EVIDENCE_INDEX.md` |
| Answers | where we stopped, what is open/blocked, next action, working sources | what was researched/observed, NOT_RUN, BLOCKED, candidates, evidence pointers |
| Authority | operational, NON_CANON | `RESEARCH_INDEX_ONLY CANON=NO RUNTIME_AUTHORITY=NO PRIMARY_EVIDENCE=NO` |

`WORKING_STATE != RESEARCH_STATE`, `RESEARCH_RESULT != USER_DECISION`, `EXPERIMENT_PASS != WORKING_DECISION`, `MODEL_PROPOSAL != USER_DECISION`, `UNKNOWN != FALSE`, `NOT_RUN != FAIL`, `BLOCKED != FAIL`.

## Surface (all read-only)

- `wm-agent-read.js` — provider-neutral. Tools: `wm_orientation`, `wm_list_projects`, `wm_list`, `wm_get`, `wm_search`, `wm_related`, `wm_project_sources`, `research_route`; agent `GUIDANCE`. `routeIntent()` is **diagnostic only** (not called at runtime, not acceptance evidence); routing authority in B1 = tool descriptions + `GUIDANCE` + explicit `plane` labels on every result.
- `working-memory.js` — only additive read accessors: `listProjects`, `listSources`, `listItemSources`, `listRelations`, `type`/`priority`/`thread` filters in `listItems`, and an optional `project_id` scope in `searchItems` that is applied **before** ranking and LIMIT. No schema change.
- `research-router.js` — **independent of Working Memory.** Parses the card fields of index §C and returns **all 19 named fields verbatim** as pointers (`card_number`, `heading`, `EXPERIMENT_ID / NAME`, `PROJECT`, `QUESTION`, `STATUS`, `EXECUTION_VERDICT`, `SCIENTIFIC_INTERPRETATION`, `WHAT_WAS_OBSERVED`, `WHAT_IT_SUPPORTS`, `WHAT_IT_DOES_NOT_PROVE`, `OPEN_FINDING`, `PRIMARY_EVIDENCE`, `GITHUB_REF`, `NOTION_REF`, `DRIVE_REF`, `NOTION_STATUS`, `DRIVE_STATUS`, `CONSISTENCY`, `LAST_VERIFIED`, `NOTES`) — including the caveats (`CONSISTENCY` such as `PARTIAL_MISMATCH` / `STALE_DRIVE`, `NOTES`). Fields that share one physical line in the index (`GITHUB_REF`/`NOTION_REF`/`DRIVE_REF`; `NOTION_STATUS`/`DRIVE_STATUS`/`CONSISTENCY`/`LAST_VERIFIED`) are each extracted separately. No verdict/status is derived or normalised from prose (there is no `execution_verdict_token`). Absent field = `null`. `card` = research CARD number, **not** a file line (`line` is accepted only as an alias). `card` + `query` together is a `VALIDATION` error. `query` is a case-insensitive substring match (every whitespace-separated term must occur) over title, name, QUESTION, STATUS, EXECUTION_VERDICT, OPEN_FINDING and PRIMARY_EVIDENCE — navigation over the current index, not an exhaustive scientific search. Authority contract (checked **first**, from the source text, never hard-coded into the response): the header block of the index (everything before the first `## ` heading) must declare each of `STATUS = RESEARCH_INDEX_ONLY`, `CANON = NO`, `RUNTIME_AUTHORITY = NO`, `PRIMARY_EVIDENCE = NO` **exactly once**, in strict **one-flag-per-line** syntax, with exactly two accepted forms: **(A) colon form** `KEY: \`VALUE\`` — one space after the colon and **both** backticks mandatory (the form the real index uses), or **(B) equals form** `KEY=VALUE` — no spaces, no backticks. An optional trailing markdown line-break `\` or trailing whitespace is tolerated; nothing else is. Anything else fails closed: `index_loaded:false`, `parse_status:"AUTHORITY_CONTRACT_INVALID"`, the problems listed in `authority_contract.problems`, no cards served, and the router's own `header` claim withheld. Violations: any other syntax, e.g. `KEY: VALUE`, `KEY: \`VALUE`, `KEY: VALUE\``, `KEY : VALUE`, `KEY:\`VALUE\``, `KEY=\`VALUE\``, `KEY = VALUE`, quoted values; a flag with another value (e.g. `CANON=YES`, lowercase `no`); a missing flag; **any duplicate declaration, including an identical one** (`CANON: NO` twice); contradictory declarations; an ambiguous value; and any combined single-line, inline-in-prose, list/bold/table or other alternative header form (not supported — never parsed as a declaration). Values are never normalised or inferred. Card bodies are not scanned (a card's own `PRIMARY_EVIDENCE:` field is not an authority flag). A valid result reports `authority_contract.declared` as read from the document.

Minimal card contract: a recognised `### N. title` heading is a valid card only if `STATUS`, `EXECUTION_VERDICT` and `PRIMARY_EVIDENCE` are present and non-empty (other fields are optional and `null` when absent). A body that is not the Evidence Index, a zero-card parse, any malformed card, or a failed fetch returns `index_loaded:false` + `parse_status` (`NOT_AN_EVIDENCE_INDEX` / `AUTHORITY_CONTRACT_INVALID` / `NO_CARDS_PARSED` / `MALFORMED_CARDS` / `INDEX_UNAVAILABLE` / `FETCH_FAILED`) and the entrypoint only; `MALFORMED_CARDS` also lists the offending `card_number`s and their missing fields, and no card is served from that index. `index_source` is `NETWORK`, `OFFLINE_CACHE`, `STALE_CACHE` or `UNKNOWN` (cached sources also set `stale:true` and a `warning`).
- `index.html` — registers the tools in `AGENT_TOOLS_SPEC` and dispatches them. `research_route` goes through the **same `WmAgentRead` bridge `execute` path as every `wm_*` tool** (one validation and error contract) yet never needs SQLite or `WmStore` (the bridge works with a null store); if Working Memory is unavailable (or its cached script is stale) the `wm_*` tools return `WORKING_MEMORY_UNAVAILABLE` while `research_route` keeps working. `GUIDANCE` is appended to the agent-loop system prompt.
- `sw.js` — `CACHE_NAME` bumped (`…-wm1`); install precaches with `cache:'reload'` (bypasses the HTTP cache so a bump cannot precache stale scripts); the exact path `docs/research/EXPERIMENT_EVIDENCE_INDEX.md` follows the **research index network policy** below (not precached, not runtime authority); everything else is unchanged.

`wm_orientation` accepts `project` or its alias `project_id` (conflicting values → `VALIDATION`, unknown → `NOT_FOUND`; the scope is never silently ignored) and returns `mode: "WORKING"`, `scope`, `projects: { items, total, truncated }` (`project_limit` default 10, max 50), `current`, `in_progress`, `open`, `blocked`, `unknown`, `next_actions`, `recent_completed` (updated_at DESC, never priority-first), `source_pointers: { items, total, truncated, included_roles: ["PRIMARY","NAVIGATION"], full_source_discovery: "wm_project_sources", omitted_project_ids, … }` (PRIMARY before NAVIGATION, per-project cap 3, total cap 15, `project_id` kept; **only the PRIMARY and NAVIGATION roles are included**, so `total`/`truncated` do not describe EVIDENCE / CONTEXT / REFERENCE sources — `wm_project_sources` lists every registered source), and `research: { available, loaded: false, entrypoint }` (`available` is true only when the research router script is really loaded; `loaded` stays false until research is actually loaded), bounded (default 5 / max 10 per bucket, with totals and truncation flags). Unresolved is exactly `OPEN / IN_PROGRESS / BLOCKED / UNKNOWN`; `CURRENT` is not unresolved; `RESOLVED != COMPLETED`; archived excluded.

Every collection output is bounded and explicit: `wm_list_projects`, `wm_project_sources`, `wm_related` return `{ items, total, truncated }` (default 20, max 50 via `limit`); `wm_get` returns `sources` and `relations` each as `{ items, total, truncated }` (defaults 10 / 20, max 50 via `sources_limit` / `relations_limit`). Nothing is dropped silently and stored data is never modified. Source lists (`wm_get`, `wm_project_sources`) are ordered by source **role** precedence (PRIMARY, then NAVIGATION, then other roles; then title, source_id); `is_primary` is only the item-link flag and is returned as separate metadata, not used for ordering.

Agent-facing text is capped in Unicode **code points**, never splitting a surrogate pair (title 200, summary 500, current_question/status_note/next_action 300, `body_md` in `wm_get` 4000); clipped fields are listed in `truncated_fields` (and `body_md_total_chars`, counted in the same Unicode code-point unit as the clip). The database is never changed and source locators are never clipped.

## Research Plane response contract

- **Direct card is complete:** `research_route({ card: N })` (alias `line`) returns **all 19 fields complete, never clipped** (e.g. card 11's `STATUS`, 533 code points). Only query results and the overview are clipped (500 / 120 code points per field, flagged in `truncated_fields`, with a note to fetch `{ card: N }` for the complete card).
- **Reachability:** a `query` returns at most 3 cards, but `matched`, `matched_card_numbers` (all matching numbers, up to 200, `matched_card_numbers_truncated` if more), `truncated` and `omitted_card_numbers` make every match discoverable; fetch each with `research_route({ card: N })`. The no-argument overview lists up to 30 cards (`card_numbers`, `omitted_card_numbers` for the rest). This is navigation over the current index, not an exhaustive scientific search.
- **Nothing meaningful is dropped silently:** a non-blank card line that is not a recognised field (e.g. a continuation line or an unknown field) or a repeated field fails the index closed with `parse_status: UNSUPPORTED_CARD_CONTENT`.
- **All-or-nothing:** `PARTIAL_INDEX_ACCEPTANCE = NOT_ALLOWED_IN_B1`. One malformed card, an unsupported card line, or an invalid authority contract makes the **whole** index unavailable (a partially malformed evidence index is not trusted). A failure response is `index_loaded: false` + `parse_status` + `entrypoint` + `diagnostics.reasons` (+ the specific `authority_contract` / `malformed_cards` / `unsupported_cards` detail); it never instructs an in-app agent to open a file it cannot open.
- **Unique card numbers:** two `### N.` headings with the same number (identical or not) fail the whole index closed with `parse_status: DUPLICATE_CARD_NUMBER` (`duplicate_card_numbers` listed); no card is served.
- **Arguments are validated before any network I/O** (pure `preflightArgs`, used by `routeWithLoader`, `route` and the bridge): an invalid request never calls the loader. `query` must be a string; `card` (alias `line`) must be a positive integer **number** (strings, 0, negatives, fractions are rejected). A blank `query` is *absent* when `card` is given (`{card:1, query:""}` runs card 1) but `{query:""}` with no `card` is `VALIDATION` (no routing request); a non-blank `query` together with `card` is rejected.
- **`index_source` / staleness:** every response carries `index_source` — `NETWORK` (fresh read, `stale:false`), `OFFLINE_CACHE` (transport failure/timeout; cached copy), `STALE_CACHE` (server 5xx or a non-index 200; cached copy) or `UNKNOWN` (`stale:null`). For the two cache sources `stale:true` and a `warning` are set and the `note` leads with that warning; a cached fallback never looks like fresh navigation.

### Research index network policy (`sw.js` + page loader)

Online-first, exact path `docs/research/EXPERIMENT_EVIDENCE_INDEX.md` only: a fresh valid network copy always beats the cache. The service worker gives the network a bounded budget (`RESEARCH_FETCH_TIMEOUT_MS`, 4 s, covering headers and body) and the page loader a longer one (`WIZ_RESEARCH_FETCH_TIMEOUT_MS`, 8 s), so a stalled connection reaches the cached fallback before the page gives up; with no valid cache it fails closed (504 → `FETCH_FAILED` / `INDEX_UNAVAILABLE`). **Strict last-known-good cache:** a network 200 may enter (or replace) the cached index only if it passes the **same strict document validator the router uses** (`ResearchRouter.validateResearchIndex`: index marker + section C, authority contract, unique card numbers, required card fields, no unsupported / unrecognised / duplicate card content) — the service worker `importScripts` the router and keeps no weaker second definition. A 200 that fails it (captive portal / proxy page, or a malformed / parse-breaking edit of the real index) never replaces the good copy; a cached copy that itself passes the validator is served instead (`sw-stale-cache`), otherwise the body is passed through un-flagged so the router fails closed with its precise `parse_status`. A cached copy is **validated before it is served** as a fallback (offline / timeout / 5xx / invalid 200): a malformed old cache is never treated as known-good. If the router script cannot be imported the service worker admits nothing and trusts no cached copy. Transport failure/timeout → cached copy flagged `sw-offline-cache`; 5xx → cached copy flagged `sw-stale-cache`; 404/410 (authoritative removal) are **not** masked by an old cache and evict it; other 4xx pass through. The strict parser in `research-router.js` remains the runtime authority.

## Tool argument contract (runtime-validated; the model's schema compliance is not relied on)

- **Limits:** omitted/`null` → the tool's default; otherwise an integer ≥ 1 (a JS number — strings, `NaN`, `0`, negatives and fractions are `VALIDATION` errors); above the tool's max the value is **clamped** and reported as `limit_clamped: { <arg>: <max> }`. Bad input is never silently turned into the default.
- **Booleans** (`includeArchived`): only real `true` / `false`; the string `"false"` is rejected, never coerced.
- **Strings:** must be strings; required ones (`query`, `work_id`, and a project for `wm_project_sources`) must be non-blank (`wm_search({})` → `VALIDATION`); optional blank filters count as absent.
- **Argument-object contract (runtime, real dispatcher included):** an argument object that is genuinely **omitted** (`undefined`) means `{}`; `null`, a number (`0`, `NaN`, …), a boolean (`false`), a string (`""`, `"text"`), an array (`[]`) or any other non-plain object is `VALIDATION` — **falsy values are never coerced to `{}`**. This is checked by the pure `WmAgentRead.preflightCall` (also used by `bridge.execute`) *before* any loader, `fetch`, SQLite init or tool code runs; the in-app dispatcher keeps its historical `args || {}` only for the legacy (non-B1) tools, and the Gemini call parser passes a present-but-falsy `args` on instead of replacing it. A plain object then gets unknown-key and tool-specific validation.
- **Unknown arguments:** each tool has an explicit allowed-argument set (its declared parameters, plus `research_route`'s `line` alias). Any other argument name — `projectId`, `include_archived`, `query_text`, `limt`, … — is a `VALIDATION` error naming the offending key and nothing is executed; a typo can never silently widen scope or change defaults.
- **Blank scope fails closed:** if `project` or `project_id` is **present** its value must be a non-empty, non-whitespace string — `""`, `"   "`, `null` or a non-string is `VALIDATION`, never "all projects". Omitting both keys is the only way to ask for all projects.
- **Scope:** `project` / `project_id` are aliases; conflicting values → `VALIDATION`; an unknown project → `NOT_FOUND`.

## Limits

- `MULTI_TAB_WRITES = NOT_SUPPORTED_IN_V0_1` (unchanged; B1 does no writes).
- `research_route` parses the current Markdown card layout; if the layout changes it degrades to pointer-only (`index_loaded:false`), never to invented claims, and never partially (see the response contract). The index is fetched over HTTP; it is not precached, so a cached fallback exists only after one online fetch.
- During the first reload after an upgrade the old service worker may still serve a cached `working-memory.js`; the `wm_*` tools then report `WORKING_MEMORY_UNAVAILABLE` (stale script) until the new service worker has taken over and the page is reloaded.
- No agent write path, approval flow, capture, or promotion (Gate B2 scope, not implemented).
- B1 enforces **data/tool-plane** separation only (every tool result carries its `plane`; research and working data are never merged by the tools). The `WORKING:` / `RESEARCH:` labelling of a model's final free-text answer is guidance, not runtime-enforced: `FINAL_MODEL_MIXED_ANSWER_ENFORCEMENT = NOT_IMPLEMENTED`. It is to be validated in a separate fresh-model validation gate.
- `FRESH_MODEL_BEHAVIOR = NOT_RUN`, `CROSS_PROVIDER_RESUME = NOT_RUN` (no real model invocation performed).
